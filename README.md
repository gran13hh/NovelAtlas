# NovelAtlas

NovelAtlas 是一个基于 AI Agent 的小说分析与创作辅助项目。用户上传包含小说正文的 TXT 文件后，系统通过可组合、可扩展的 Agent 与 Skills，对长篇内容进行拆分、检索、分析、归纳、生成和导出。

> 当前阶段：阶段 1“前后端最小可运行骨架”已验收，阶段 2“TXT 上传与临时文件生命周期”即将开始。本文档中的技术选型是首版建议，可在实现阶段按实际需求调整。

完整的分阶段范围、状态和验收标准见 [`PLAN.md`](PLAN.md)。项目严格按阶段开发，当前阶段经手动验收后才进入下一阶段。

## 项目目标

将小说原文转化为结构化、可追溯、可阅读的“小说图谱”，帮助用户理解剧情、人物、文风与世界观，并基于分析结果进行风格仿写和视觉内容生成。

## 核心功能

### 1. 剧情与故事线

- 按卷、章、场景或事件整理剧情摘要。
- 提取主线、支线、伏笔、冲突、转折与关键事件。
- 建立事件时间线，并标注相关人物、地点和原文依据。
- 支持从全书概览逐层下钻到章节与典型段落。

### 2. 人物档案与人物关系

- 提取人物姓名、别名、身份、首次出场和重要经历。
- 整理外貌、衣着、性格、能力、行为特点和人物弧光。
- 分析人物之间的关系及其变化。
- 保留对应章节或原文片段，减少无依据推断。
- 根据人物档案生成可编辑的提示词，并调用生图模型生成人物印象图。

### 3. 写作手法与文风分析

- 分析叙事视角、节奏、句式、用词、修辞和情绪表达。
- 分别总结战斗、景物、外貌、服装、对话等描写特点。
- 收集具有代表性的典型段落，并注明出处。
- 区分“从原文得到的结论”与“模型的分析或推断”。

### 4. 世界观与地图

- 整理时代背景、地理区域、势力、制度、文化、种族、能力体系和重要物品。
- 提取地点之间的方向、距离、隶属、通行路线与事件关联。
- 根据结构化地理信息生成地图描述与提示词，并调用生图模型生成地图草图。
- 对原文未明确的信息标记为未知、冲突或推测，避免将生成内容当作原著设定。

### 5. 风格仿写

- 用户输入剧情梗概、人物、场景、篇幅和限制条件。
- Agent 检索相关文风特征与示例，生成具有相近抽象特征的新段落。
- 支持展示使用的风格标签和生成依据。
- 默认避免大段复现原文，并提示用户仅处理其有权使用的内容。

### 6. 结果导出

- 将单本小说的分析结果导出为 Word（`.docx`）或 HTML。
- 导出内容可包含目录、剧情线、人物档案、关系、文风、世界观、引用来源和生成图片。
- 导出前允许用户选择模块、排序方式和是否包含图片/原文引用。

### 7. 可扩展能力

后续功能通过新增 Agent、Skill、工具适配器或导出模板实现，尽量避免修改核心流程。

## 产品约束

- 首版支持 TXT 小说文件；编码检测、章节识别与超长文本处理需要纳入实现范围。
- 不提供注册和登录功能。
- 不持久化存储用户数据；上传文件、解析结果和中间产物仅在当前任务或临时会话中使用，并按策略清理。
- 前端不得暴露模型供应商的密钥；模型调用统一由后端执行。
- 分析结果应尽可能附带章节、段落或文本位置，便于用户核验。
- 对缺失、互相矛盾或由模型推断的信息做明确标记。

## 初步技术方案

### 总体架构

```text
Web 前端
  │ 上传 TXT / 配置任务 / 查看与编辑结果 / 导出
  ▼
后端 API
  │ 文件校验、任务编排、流式进度、临时数据、导出
  ▼
Agent 编排层
  ├─ 小说解析与分块
  ├─ 剧情 Agent
  ├─ 人物 Agent
  ├─ 文风 Agent
  ├─ 世界观与地图 Agent
  ├─ 仿写 Agent
  └─ 报告 Agent
  │
  ├─ Skills：章节识别、实体归并、引用定位、提示词生成等
  ├─ Tools：检索、结构化输出、图片生成、DOCX/HTML 导出等
  └─ Model Gateway：文本分析模型与图片生成模型分别选择
```

### 建议技术栈（待实现阶段确认）

- 前端：React / Next.js + TypeScript。
- 后端：Python + FastAPI。
- Agent 编排：LangGraph，或兼容同类 Agent 框架的自定义编排层。
- 数据校验：Pydantic，所有 Agent 输出使用明确的结构化 Schema。
- 临时检索：进程内或临时目录中的向量/全文索引，不使用长期用户数据库。
- 导出：HTML 模板与 DOCX 生成工具。
- 测试：后端 `pytest`，前端单元测试与端到端测试。

## Agent 与 Skills 设计原则

- **职责单一**：每个 Agent 只负责一个明确领域，编排器负责依赖和重试。
- **Skills 可复用**：将章节切分、人物别名归并、证据引用、地图提示词生成等能力做成独立 Skill。
- **结构化输出**：Agent 之间传递经过校验的数据对象，而不是无约束文本。
- **证据优先**：重要结论附带原文位置；无法确认时返回不确定性，而不是补写事实。
- **长文本分层处理**：先分块提取，再分章节归纳，最后做全书级合并与一致性检查。
- **人工可编辑**：允许用户修正人物、关系、地点和分析结论，再用于生图、仿写与导出。
- **可观测与可恢复**：记录任务步骤、耗时、失败原因和可重试状态，但不记录不必要的用户正文。

## 模型调用与切换

文本分析和图片生成采用两套独立配置，通过统一接口隔离具体供应商：

```text
TextModelProvider
  ├─ 分析/抽取模型
  ├─ 长上下文模型
  └─ 仿写模型

ImageModelProvider
  ├─ 人物印象图模型
  └─ 地图生成模型
```

计划支持：

- 在配置文件或界面中分别选择文本模型与生图模型。
- 为不同 Agent 指定不同模型、参数、超时和重试策略。
- 支持兼容 API、自定义 Base URL 和本地模型适配器。
- 密钥仅从后端环境变量或安全配置读取，不提交到 Git。
- 模型不可用时返回明确错误，并允许更换供应商后重试。

## 核心工作流

1. 用户上传 TXT，后端完成格式、大小、编码与内容校验。
2. 系统识别章节并分块，为每个文本块保存可追溯的位置标识。
3. 各分析 Agent 并行或按依赖运行，生成结构化中间结果。
4. 一致性检查合并人物别名、时间线、地点和重复事件。
5. 用户查看、检索和修正结果，可选择生成角色图或地图。
6. 仿写 Agent 根据用户剧情与已确认的文风特征生成内容。
7. 报告 Agent 将选定模块导出为 DOCX 或 HTML。
8. 会话结束后清理上传文件、索引和中间产物。

## 非功能需求

- **隐私**：默认最小化日志内容，不记录小说全文、密钥或完整模型请求。
- **安全**：校验文件类型和大小；防止路径穿越、提示词注入和不安全 HTML 输出。
- **可靠性**：任务支持超时、重试、取消和失败步骤恢复。
- **性能**：对长篇小说采用增量、分层和可并行处理，并显示实时进度。
- **可测试性**：模型接口可替换为测试桩；关键分析结果使用固定样例做回归测试。
- **可维护性**：供应商适配、Agent、Skill 与业务 Schema 解耦。
