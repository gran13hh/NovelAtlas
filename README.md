# NovelAtlas

NovelAtlas 是一个基于 AI Agent 的长篇小说细纲生成项目。用户上传包含小说正文的 TXT 文件后，系统按模型输入容量组合相邻章节，逐批概括重要内容，再将批次结果分层汇总为可阅读、可追溯的全书细纲。

> 当前阶段：阶段 0～5 已验收。下一步开发阶段 6 的细纲工作台与人工修正。

完整的分阶段范围、状态和验收标准见 [`PLAN.md`](PLAN.md)。项目严格按阶段开发；阶段 5 的子步骤在 5E 完成后统一验收。

## 本地一键启动

macOS 可以直接双击项目根目录的 `start.command`。启动程序会检查 `.venv` 和 npm 依赖，同时启动 FastAPI 与 Vite，服务就绪后自动打开浏览器；在终端窗口按 `Ctrl+C` 会同时关闭前后端。

也可以在 PyCharm 或终端中运行：

```bash
.venv/bin/python scripts/dev.py
```

只检查环境而不启动服务：

```bash
.venv/bin/python scripts/dev.py --check
```

如需手动指定端口或禁止自动打开浏览器：

```bash
.venv/bin/python scripts/dev.py --api-port 8000 --web-port 5173 --no-open
```

## 项目目标

将长篇小说转化为稍微细致、按章节范围可回看的全书大纲，帮助用户快速了解主要剧情、人物关系、世界观、故事线、伏笔和未解决事件。结果定位为阅读辅助，不代替用户对原著的人工梳理。

## 核心功能

### 1. TXT 解析与批次规划

- 识别 TXT 编码、章节标题和正文边界。
- 对超长章节进行安全分块，并保留稳定章节和文本块 ID。
- 根据用户配置的模型上下文、预留输出和安全余量，动态组合相邻短章节。
- 优先保留完整章节；只有单章超出输入预算时才按文本块拆分。

### 2. 分批重要内容概括

- 每次请求处理一个由连续章节或文本块组成的原文批次。
- 概括关键事件、参与人物、关系变化、世界观线索、伏笔和未解决事项。
- 某类信息没有出现时返回空结果，不为填满栏目而补写内容。
- 每个批次成功后立即保存，失败重试时不重新调用已完成批次。
- 模型返回必须通过结构化 Schema 和来源 ID 白名单校验；正文中的提示词或命令一律视为小说内容。

### 3. 全书细纲汇总

- 将全部批次概括按 Token 预算进行一次或多层汇总。
- 生成总体概述、章节范围细纲、主要故事线和关键转折。
- 归纳主要人物、人物关系及其阶段性变化。
- 归纳地点、势力、规则、功法、物品等主要世界观内容。
- 对跨越较远章节的疑似伏笔、关联和冲突明确标记不确定性。

### 4. 任务进度与恢复

- 分析前展示批次数、预计模型调用次数和输入 Token。
- 通过 SSE 展示当前批次、进度和错误。
- 以批次为最小 Checkpoint；网络恢复后从失败批次继续。
- 批次状态和结果保存在上传任务临时目录，后端重启后在任务未过期时可恢复。
- 浏览器 API Key 不写入任务文件；重启后继续远程任务时由浏览器重新提交。

### 5. 结果查看与导出

- 在工作台查看总体概述、批次概括和全书细纲。
- 允许用户修正细纲、人物关系、世界观和故事线。
- 后续将确认后的细纲导出为 Word（`.docx`）或 HTML。

### 暂不开发的后续能力

如果输入小说仍在连载，未来可以基于已经确认的细纲辅助续写。当前仅在路线中保留这一可能性，不预留页面开关、API、Schema 或占位模块。

## 产品约束

- 首版支持 TXT 小说文件；编码检测、章节识别与超长文本处理需要纳入实现范围。
- 不提供注册和登录功能。
- 后端不长期持久化用户数据；上传文件、解析结果和中间产物仅在当前任务或临时会话中使用并按策略清理。用户明确保存的模型连接配置属于浏览器本地例外，可随时清除。
- 服务端 `.env` 密钥不得返回前端；用户也可明确选择把另一份模型配置缓存在当前浏览器，浏览器 Key 会以明文存入该站点的 localStorage，并只随模型操作发送给后端。
- 分析结果应尽可能附带章节、段落或文本位置，便于用户核验。
- 对缺失、互相矛盾或由模型推断的信息做明确标记。

## 初步技术方案

### 总体架构

```text
Web 前端
  │ 上传 TXT / 配置任务 / 查看与编辑结果 / 导出
  ▼
后端 API
  │ 文件校验、任务编排、流式进度、临时数据、导出
  ▼
Agent 编排层
  ├─ 小说解析与分块
  ├─ 动态批次规划
  ├─ 批次概括 Agent
  ├─ 分层汇总 Agent
  └─ 细纲报告 Agent
  │
  ├─ Skills：批次规划、批次概括、Checkpoint、全书汇总
  ├─ Tools：Token 计数、结构化输出、DOCX/HTML 导出
  └─ Model Gateway：可切换的文本模型
```

### 建议技术栈（待实现阶段确认）

- 前端：React + TypeScript + Vite。
- 后端：Python + FastAPI。
- Agent 编排：LangGraph，或兼容同类 Agent 框架的自定义编排层。
- 数据校验：Pydantic，所有 Agent 输出使用明确的结构化 Schema。
- 临时检索：进程内或临时目录中的向量/全文索引，不使用长期用户数据库。
- 导出：HTML 模板与 DOCX 生成工具。
- 测试：后端 `pytest`，前端单元测试与端到端测试。

## Agent 与 Skills 设计原则

- **职责单一**：批次 Agent 只负责当前原文批次的重要内容概括，汇总 Agent 只负责在批次结果上生成全书细纲。
- **Skills 可复用**：将 Token 预算、相邻章节装箱、批次持久化、分层汇总做成独立 Skill。
- **结构化输出**：Agent 之间传递经过校验的数据对象，而不是无约束文本。
- **章节可追溯**：重要内容保留来源章节或文本块 ID；无法确认时返回不确定性，而不是补写事实。
- **长文本分层处理**：先对原文批次生成较细概括，再对批次结果逐层归并，最后生成全书细纲。
- **人工可编辑**：允许用户修正批次概括和全书细纲，再用于后续导出。
- **可观测与可恢复**：每个批次成功后立即落盘，记录调用次数、Token、失败原因和恢复位置，但不保存 API Key。

## 模型调用与切换

项目只保留文本模型配置，通过统一接口隔离具体供应商：

```text
TextModelProvider
  ├─ 批次概括模型
  └─ 全书汇总模型
```

计划支持：

- 在配置文件或浏览器界面中选择文本模型。
- 配置模型上下文窗口、单次输入预算、输出预留、安全余量、超时和重试策略。
- 支持兼容 API、自定义 Base URL 和本地模型适配器。
- 支持服务端环境变量，以及用户主动保存的浏览器本地配置；两者都不能提交到 Git。
- 模型不可用时返回明确错误，并允许更换供应商后重试。

阶段 4 已验收的文本模型能力：

- 不需要密钥、不会联网的本地 Mock 验证。
- OpenAI Responses API 兼容文本适配器。
- 超时、有限重试、统一错误和公开配置脱敏。
- 浏览器文本模型配置、`GET /models` 连接测试、模型选择与版本化 localStorage 缓存。

阶段 4 中曾提交的图片模型配置、适配器、路由和界面已在阶段 5A 清除，目前只保留文本模型链路。

具体环境变量及安全占位值见 [`.env.example`](.env.example)。服务端模式下，真实 API Key 只写入未提交 Git 的本地 `.env`。浏览器模式会将用户输入的 Key 明文保存在当前站点的 localStorage 中，安全性低于 `.env`，仅适合可信个人设备，并应在不再使用时通过界面清除。

分析提示词与正文会在真正调用前再次计算 Token；安全余量最低为 512 Token，默认 2000 Token。默认临时任务目录位于操作系统临时目录的 `novelatlas-uploads`，关闭后端不会立即删除，任务会在 TTL 到期、用户主动删除或清理任务运行时移除，因此可以在后端重启后继续处理。

原阶段 5 已实现但不再采用的内容：

- 逐文本块调用摘要模型，不能组合多个短章节。
- 先压缩为章节摘要，再让剧情、人物、文风、世界观 Agent 分别读取摘要。
- 只在 LangGraph 节点结束后 Checkpoint，无法从已完成的原文批次继续。

这些代码尚未提交 Git，并已在阶段 5A 清除。新的后台任务、SSE、结构化校验、Agent 与 Skills 将围绕批次概括和全书细纲重新建立。

阶段 5 API：

```text
GET  /api/analyses/config           # 读取服务端默认 Token 预算
POST /api/analyses/{task_id}/plan   # 生成并保存批次计划，不调用模型
GET  /api/analyses/{task_id}/plan   # 读取最近一次有效批次计划
POST /api/analyses/{task_id}/run    # 启动或继续批次概括、分层汇总与最终细纲
GET  /api/analyses/{task_id}/run    # 查询批次、汇总层级及最终结果的持久进度
GET  /api/analyses/{task_id}/events # 订阅精简 SSE 进度；断线不取消后台任务
GET  /api/analyses/{task_id}/summaries # 读取目前已完成的结构化批次概括
GET  /api/analyses/{task_id}/outline # 读取已完成的全书细纲
```

同一个 `run` 启动接口同时承担失败恢复：再次提交模型配置后，从首个未完成批次、当前汇总节点或最终细纲节点继续。每个中间结果先独立原子写入，再更新任务清单，因此已完成调用不会因后续网络错误或后端重启而重做。高层汇总只在提示词中引用直接下层节点，服务端再展开并保留完整批次/章节来源，避免长篇输入反复携带庞大的来源 ID 列表。SSE 从同一持久清单读取精简进度，关闭或重连订阅不会取消 Agent；事件不包含正文、API Key 或 Base URL。

## 核心工作流

1. 用户上传 TXT，后端完成格式、大小、编码与内容校验。
2. 系统识别章节并分块，为每个文本块保存可追溯的位置标识。
3. 根据文本模型 Token 预算组合相邻章节，并展示批次与预计调用次数。
4. 批次概括 Agent 逐批处理原文，每批完成后立即保存结果和恢复游标。
5. 汇总 Agent 对批次概括进行一次或多层归并，生成全书细纲。
6. 用户查看并修正批次概括、人物关系、世界观、故事线和最终细纲。
7. 报告 Agent 将确认后的细纲导出为 DOCX 或 HTML。
8. 会话结束、用户删除或任务过期后清理全部临时产物。

## 非功能需求

- **隐私**：默认最小化日志内容，不记录小说全文、密钥或完整模型请求。
- **安全**：校验文件类型和大小；防止路径穿越、提示词注入和不安全 HTML 输出。
- **可靠性**：任务支持超时、重试、取消和失败步骤恢复。
- **性能**：对长篇小说采用增量、分层和可并行处理，并显示实时进度。
- **可测试性**：模型接口可替换为测试桩；关键分析结果使用固定样例做回归测试。
- **可维护性**：供应商适配、Agent、Skill 与业务 Schema 解耦。
